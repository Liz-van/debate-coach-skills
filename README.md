# debate-coach-skills

中文辩论备赛用的四个 Agent Skills。需要 DSH、Claude Code 这类能读本地技能目录、能起子 Agent 的环境。

拿到辩题之后有三条路：只打我方这一边；正反两边各出一套立论；或者让十一个 Agent 打一场完整的四对四。另外还有一个给外行看的辩题速览。

## 四个技能

| 技能 | 触发 | 干什么 |
|---|---|---|
| argument-construction | `$立论 <辩题> <持方>` | 只做我方这一边。内部起两个 Agent，一个立论、一个当对手，对抗收敛之后再落稿，出 md 报告和 xlsx 资料表 |
| dual-side-argument | `$立论 <辩题>` | 不给持方就走这条。正反两方各出一套完整立论，两边各过一遍质检，最后给对位比较 |
| debate-9 | `$立论 <辩题>` | 不给持方也可以走这条。十一人赛制：正反各四名辩手、一名评委、双方各一名资料员，四对四打满赛程，赛后交两套立论、各辩位稿件和一份辩论实录 |
| motion-brief | `$评赛 <辩题>` | 中立速览，出 md 或 PDF。不站队、不查资料、不做攻防预判，让没打过这道题的人先看懂争点在哪 |

`dual-side-argument` 和 `debate-9` 的触发词一样，按你的意图挑：想先拿到两套立论走前者，想真打完一场走后者。这两个技能都要用 argument-construction 里的版块、写作风格、诊断卡、资料协议和脚本，所以四个目录得放在同一个技能根目录下。

## 对抗是怎么打的

单持方模式下，我方 Agent 写第一稿的时候，另一个 Agent 同时在准备打它；双持方模式下两个 Agent 天然互为例手，正方那个还要同时扮反方去打反方的草案。两方必须用同一个模型、同一个思考等级。模型不一样的话，模型差异会被当成论证差距，两条对抗线的裁决一起失效。

## 质检卡点

`check_debate.py` 卡几条硬项。首轮草案登记的论点少于三条，直接判失败。对抗打完，"存活" 和 "修补后存活" 的论点加起来必须够三条。报告第四节的持方论点体系里一旦出现「对方会……」「反方可能……」，脚本就报错——对手的话要留在对手那一栏，写我方的论点体系时不替对方说话。一方过不了硬项，不许只交另一方的半份成品。

写作上另有一份去 AI 腔清单写在 `argument-construction` 的写作风格小节里：禁宣传腔，禁「专家认为」这类模糊归因，禁句尾挂「凸显 / 体现」，禁排比凑三项，术语第一次出现要给一句白话解释。辩论实录按同一份清单写。

## 安装

把 `skills/` 下四个目录复制进你的技能根目录：

```
~/.dsh/skills/        # DSH
~/.claude/skills/     # Claude Code
```

技能文档里的路径统一按 `~/.dsh/...` 写。换到别的环境时改三处：

| 文档里写的 | 换成 |
|---|---|
| `~/.dsh/skills` | 你的技能根目录 |
| `~/.dsh/tmp` | 随便一个临时目录。中间 JSON、HTML、PDF 都落这里，交付目录不留临时文件 |
| `~/debate` | 你的备赛目录，`备赛/` 和 `评赛/` 两个子目录会自动建 |

## 依赖

Python 3.10 以上，跑 `check_debate.py`、`precheck.py`、`generate_report.py`、`check_match.py`、`count_speech.py`、`speech_bands.py`；生成 xlsx 要 openpyxl。

出 PDF 是可选环节，不出不影响其他部分。本机的做法是 pandoc 加 weasyprint，CSS 里指定了 Windows 自带的微软雅黑，非 Windows 环境要自己改字体。

脚本里有几处按 Windows 处理的地方：控制台是 GBK 时强制 UTF-8 输出，免得 ✓ / ✗ 报 UnicodeEncodeError；读带 BOM 的 JSON；过滤 Windows 文件名非法字符。这些在 Linux 和 macOS 上不影响运行。

## 几点说明

这套技能是在真备赛里改出来的，跑过三场完整的九人赛制比赛，赛后复盘又动过质检项。

原作者机器上的绝对路径（技能目录、临时目录、备赛目录、Python 解释器路径）都换成了上表的通用路径，技能逻辑本身没动。

正文和脚本大多是我和 AI 一起写的，逐轮试过、也反复改过，不是纯手写。

赛题、稿件、报名表这些备赛资料不在仓库里。
