# 双 Agent 对抗收敛：两个持方互殴，收敛出一份立论

论点是**打出来的**，不是一个人坐在桌前想出来的。本流程强制开两个 agent：一个替我方持方立论，一个站对面往死里打。打完由 Lead 逐条裁决，只把**没被打死**的部分写进最终立论。

> ⚠️ 与「立论不预判对方反驳」不冲突（用户既定规矩）：对抗发生在**工作过程**里，用来暴露并修好论证链上的漏洞；**最终立论正文（§4）不许出现「对方会说……我方回……」**。对抗中产生的真实攻击与我方回应，一律落到 §6「反方观点与反驳」与 §8「攻防预判」；修补后的论证落回 §4；全过程的攻防记录进报告附录。

## 一、三个角色

| 角色 | 谁来做 | 干什么 | 不许干什么 |
|---|---|---|---|
| **主笔**（立论方 agent） | 独立 agent | 按我方持方构造与维护论点体系；逐条回应攻击：修补 / 换证据 / 改判准 / 让步删点 / 拒绝并说明 | 不许为了不被骂而模糊主张；不许把「对方会这么打」写进立论正文 |
| **对手**（反驳方 agent） | 独立 agent | 站另一持方，用**最强版本**攻击；每条攻击指名到论点编号 + 具体环节 + 依据 + 严重程度 | 不许打稻草人；不许编数据；不许用「不够打动人」这类主观评价；不许为了打而打 |
| **Lead**（主持人） | 当前会话主 agent | 派活、限轮、验收格式、**逐条裁决**、写最终立论 | 不许下场当第三辩手；不许替任何一方补论证；不许虚构战果 |

主笔与对手**必须是两个不同的 agent 实例**。Lead 自己分饰两角只在工具不可用时兜底，且必须在附录标注（见第六节）。

## 二、开工前必须锁死的四项（不锁死就开打 = 白打）

两个 agent 各自收到同一份前置材料，缺一项就先补齐再开打：

1. **同一份辩题诊断卡**：命题类型、论证结构、关键词最低证明标准、当前采用的读法。两方读法不一致 → 先修诊断卡，否则是在打两道不同的题。
2. **同一套举证责任分配**：只有方向相反（我方要证什么、对方可只证到哪一步），不允许一方偷偷降低自己的义务。
3. **同一批事实基准**：交锋必须落在同一批事实上（同一指标、同一时段、同一口径）。对手若引入新事实，必须给出可查来源，主笔有权要求它进事实交锋点表。
4. **同一套语言与档位**：档位（精简 / 标准 / 完整）决定对抗轮数与覆盖下限，两方一致。**论点个数不随档位变**——三档都是固定 3 个论点。

## 三、共享事实，但各自独立检索

- 两方**各自**执行检索与核验（`evidence-protocol.md`），证据状态各自标注。
- 对抗中引用的证据必须带来源编号 `[n]` + 证据状态；**来源编号分侧独立**，`[3]` 在主笔侧与对手侧含义不同，禁止互相引用对方编号冒充自己的证据。
- 对手可以只给**逻辑反驳**（无外部材料），但必须显式标注 `依据：逻辑反驳`，不得伪装成有数据支撑。
- 同一条事实，两方读出相反结论 → 写作「来源冲突」进事实交锋点，不许各写一半蒙过去。

## 四、回合制协议（字段名固定，脚本按此校验）

每轮 = **对手攻击 → 主笔修补**。轮数按档位：精简 1 轮 / 标准 2 轮 / 完整 3 轮。

这里的轮数是**首轮收敛**的预算。用户标了 `【讨论】` 以后追加的**讨论轨**（第九节）另算，既不吃这个上限，也不放宽它——首轮该跑的轮数与攻击数下限一条都不少。

### 主笔首轮交的草案

草案**固定交 3 个论点**（三档一致，不随详细程度增加；完整档加的是证据密度与对抗轮数）。每个论点给：编号 `A1/A2/A3` + **一句话主张** + 逻辑链预览（箭头链）+ 主要事实依据（来源编号 + 证据状态）。草案是**靶子**，不必写得像成稿。

### 对手的攻击（每条一格）

```
AT<n>：
  目标论点：A1
  环节：机制            ← 六环之一（事实前提/机制/中间结果/最终影响/评价标准/辩题结论）
                          或 证据 / 概念 / 比较 / 语言 / 结构
  谬误：滑坡            ← 有才填，没有写「无」；填了要能说清哪一步不成立
  严重程度：致命 | 重要 | 次要
  攻击主张：一句话说清「哪一步不成立」
  依据：[3] 2019 年某口径数据 / 逻辑反驳：A 推不到 B 因为……
  最低修补要求：主笔必须做到什么这轮才算闭合（可执行、可证伪）
```

规则：

- 每条攻击**只能打一个环节**，说不清环节的攻击无效。
- 攻击数量与覆盖面下限（`check_debate.py` 硬项 / 软项）：精简 ≥2 条、覆盖 ≥1 个论点；标准 ≥3 条、覆盖 ≥2 个；完整 ≥5 条、覆盖 ≥2 个——只打一个点说明对手没尽责。
- **必须 steelman**（`attack-defense.md` 第一节）：用主笔能认可的语言复述其最强版本再打。
- 第二轮起**只打**「上轮修补后仍未闭合的点」或「修补引入的新问题」；重复已被有效修补的攻击 = 无效攻击，Lead 记录在案。
- 最后一轮结束后（标准 / 完整档），对手补一段**判决陈述**：如果现在开打，我方（对手）打算怎么赢，给出 2–3 个真正的胜负点。这段是 §8 攻防预判和 §9 结辩建议的原料。

### 主笔的修补（每条一格）

```
D<n>：
  对应攻击：AT1
  处理动作：修补 | 换证据 | 改判准 | 让步删点 | 拒绝并说明
  具体怎么改：……（写清改后那条论证链长什么样）
  代价：……（让步之后我方在哪个比较上变弱，必须诚实写）
```

规则：

- **每条攻击都要有回应**，不许沉默；「拒绝并说明」必须给出理由（对方误读、诉诸完美、依据不成立……）。
- **致命级攻击不许只靠「拒绝」顶回去**：必须真改（修补/换证据/改判准/让步删点），或者由 Lead 判删。
- 修补后论点体系若掉到 3 个以下 → 回第二步补料或改结构，**不许硬凑**（也不许把删掉的论点换个名字塞回来）。

## 五、Lead 的裁决

一条攻击算「**成立**」需同时满足：① 说得出是哪一环不闭合；② 带依据（核验来源 / 可复现反例 / 自洽的逻辑反驳）；③ 它的修补要求是我方能做到的——要求「彻底解决问题」属于诉诸完美，判不成立。

逐条论点给结局（`check_debate.py` 硬项）：

| 结局 | 条件 | 后续处理 |
|---|---|---|
| 存活 | 未被有效攻击，或攻击不成立 | 直接进 §4 |
| 修补后存活 | 攻击成立，主笔的修补让论证链重新闭合，且证据仍支撑 | 用**修补后**的版本进 §4 |
| 降级 | 不能独立成立，但并进另一论点当次要栏后仍成立 | 进 §4 对应论点的次要栏，不再算独立论点 |
| 删除 | 修不了、并进去也不行 | 从 §4 删掉；重算我方还剩几条，**少于 3 个则回炉**（论点固定 3 个，三档一致） |

裁决必须逐条写理由。攻击不成立的，也在裁决表里留一行——这行直接变成 §6「我方为什么能这么回」的攻防料。

## 六、机制选择与降级路径（按优先级）

1. **Agent Teams**：`spawn_teammate` 起两个 durable teammate（主笔 / 对手），Lead 用 `send_message` 逐轮派活、`wait_agent` 等回。首选，可中断、可续跑。
2. **subagent**：用 `subagent` 起两个后台子 agent，用返回的 id 通过 `send_message` 续跑下一轮。适用于没有 Agent Teams 的会话。
3. **兜底**：Lead 自己分饰两角。**必须分两次独立成稿**——先单独写对手的攻击稿（写的时候只站对面），再单独写主笔的修补稿；禁止一边写一边替自己辩解。附录标注「本次未使用双 Agent 对抗，为单 Agent 分角色」，并在 `debate.json` 里把 `fallback` 设为 `true`。

成本控制（硬性）：

- 单轮消息**只传变化量**：上一轮结论摘要 + 本轮任务 + 需要的论断编号，不重传全文。
- 轮数到上限强制收敛，不许「再来一轮更狠的」。
- 两个 agent 之间不私下串话，一切通过 Lead 转发；Lead 是唯一的消息中枢。

## 七、红线（违反即整轮作废）

1. **不许编数据、编来源、编案例**。对手方最容易为了打而打，查不到真材料就只能用逻辑反驳并标注类型。
2. **不许改我方持方**。吵到最后立场跑偏，等于没立论。
3. **不许打稻草人**，也不许把对方最弱的一条当代表作打。
4. **立论正文不预判反驳**（见文首提示）：§4 只写我方主张与论证。
5. **不许虚构战果**：裁决表只写实际发生的攻防；场上的承认、矛盾、未回应，没发生就不写。
6. **不许两边放水**：对手的「攻击不成立」必须由 Lead 按第五节标准判，不由主笔自称。

## 八、记录格式与脚本

对抗记录写 `~/.dsh/tmp/<任务名>/debate.json`（全局 R6，不许落在交付文件夹），结构：

```json
{
  "motion": "辩题",
  "side": "正方",
  "tier": "标准",
  "roles": {"proposer": "主笔 agent 名", "opponent": "对手 agent 名", "judge": "Lead"},
  "fallback": false,
  "arguments": [{"id": "A1", "claim": "一句话主张"}],
  "rounds": [
    {"n": 1,
     "attacks": [{"id": "AT1", "target": "A1", "link": "机制", "fallacy": "滑坡",
                  "severity": "致命", "claim": "……", "basis": "[3] ……", "demand": "……"}],
     "defenses": [{"id": "D1", "attack": "AT1", "action": "修补",
                   "detail": "……", "cost": "……"}]}
  ],
  "opponent_final": "判决陈述：对手打算怎么赢 + 2-3 个胜负点",
  "verdicts": [{"target": "A1", "result": "修补后存活", "reason": "……"}],
  "discussion": [
    {"n": 1,
     "trigger": "用户标【讨论】时提出的质疑 / 方向（照他的话记，不必逐字）",
     "attacks": [{"id": "AT1", "target": "A2", "link": "比较", "fallacy": "无",
                  "severity": "重要", "claim": "……", "basis": "逻辑反驳：……", "demand": "……"}],
     "defenses": [{"id": "D1", "attack": "AT1", "action": "换证据", "detail": "……", "cost": "……"}],
     "verdicts": [{"target": "AT1", "result": "成立", "reason": "……"}],
     "changed": ["§4 A2 第二段（比较判准换成…）", "§6 O3 反驳四步"]}
  ]
}
```

讨论项说明：`trigger` 必须有；讨论轮的攻击 `target` 允许写 `判准` / `全局`（质疑不是针对某一个论点时）；`verdicts[].result` 只取 `成立` / `不成立`；`changed` 逐项写清**改了哪一节、哪个编号、改了什么**——它是「只改受影响章节」这条规矩的凭据。讨论轮**不计入** `rounds`，也不计入 H4 的攻击总数下限；H11–H14 单独卡它。

出文件前先跑：

```powershell
python ~/.dsh/skills/argument-construction/scripts/check_debate.py <debate.json> --md <报告.md> --tier <档位>
```

脚本能查的硬项（轮数不足、攻击缺环节/缺依据/编号重复、有攻击没修补、致命攻击没真改、有论点没裁决、§4 预判反驳、讨论轮缺 `trigger`/缺回应/缺裁决/`changed` 为空）不通过就先修再出文件。脚本查不到、必须人工核对的两条：**被删或被降级的论点不许换个名字写回 §4**；**裁决表里「攻击不成立」的那几行，理由要与 §6 的回应口径一致**。

附录里放**对抗收敛记录**：轮次、攻击数与严重程度分布、修补表、裁决表、以及未闭合项（如果有，写清为什么不影响胜负）。讨论轨的轮次与裁决并进同一份记录，不另开小节。

## 九、讨论轨（只在用户标【讨论】时追加）

**触发条件是唯一的**：用户消息里出现标记词 `【讨论】`。没有这个标记，他的任何疑问都走普通对话——直接回答、直接改稿，**不开对抗**；Lead 不许自行判断「这个质疑值得再打一轮」而擅自开打。

一轮讨论 = **一条追加对抗轮**：

1. **锁定靶心**：把用户的质疑或方向当成本轮**唯一**议题，记进 `discussion[].trigger`。不许顺手把其它论点重打一遍，也不许借机重跑首轮对抗。
2. **重新站边**：优先用 `send_message` 把新任务派给同一对 agent（主笔仍是我方、对手仍是对面，同一个 agent 不许在讨论轮里换边）；agent 不可用时按第六节优先级重起，兜底照旧标 `fallback: true`。**同模型同思考等级**照旧。
3. **攻防**：对手只围绕靶心出最强攻击（字段与第四节完全一致，含 steelman 与最低修补要求）→ 主笔逐条回应（处理动作 / 具体怎么改 / 代价）。
4. **裁决**：Lead 逐条判 `成立` / `不成立`，标准同第五节（说得出哪一环、带依据、修补要求是我方能做到的）。判「不成立」必须写理由；**靶心本身站不住就直说**，不许为了顺从用户而假装它成立——顺从换不来赛场上站得住的立论。
5. **只改受影响章节**：按裁决改 `§4` / `§6` / `§8` / 附录对抗记录里的**相关部分**，改动逐项写进 `changed[]`（哪一节、哪个编号、改了什么）。**不许借讨论轮重写全篇**，也不许顺手改与靶心无关的内容。
6. **不占档位轮数**：档位 1/2/3 轮是首轮收敛的预算，讨论轮是追加——既不放宽首轮下限，也不会因为「没有讨论轮」而免掉那些检查；讨论轮自己跑 H11–H14。
7. **重跑校验**：改完重跑 `check_debate.py`（报告 md 变了就带上 `--md`），硬项通过才交新版；报告的封面版本说明加一行「第 n 轮讨论：靶心 → 改了什么」。
8. 讨论轮若改了某个论点的结局，**同步更新顶层 `verdicts`**（H8/H9 以顶层为准）；删到少于 3 个论点照样回炉补料或改结构。

一条消息里给了多个质疑 → 按顺序拆成多条讨论轮（`n` 递增），**每轮只打一个靶心**。默认一条靶心一轮，不自动追加；只有靶心明显未闭合（裁决没落地、或主笔的修补没写清）才加一轮。
