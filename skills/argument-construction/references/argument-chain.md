# 论证链检查与谬误定位

> 方法框架整理自 athena-caixinying/debate-prep（MIT）与 hellobiyue/debate-prep-workbench（MIT）。

## 一、论点三段式

每个论点必须包含：

1. **逻辑链预览**：箭头链一句话讲完整条论证路径
2. **展开叙述**：理论解释 + 事实论据 + 引用出处，语言有「辩感」
3. **收束**：自然上升到辩题价值层面，不另起「升华点」标签

## 二、论证链六环自检（逐环打勾，不得跳环）

把每个论点改写成：`事实前提 → 机制 → 中间结果 → 最终影响 → 评价标准 → 辩题结论`

| 环节 | 检查问题 |
|---|---|
| 事实前提 | 是否真实、是否合题、是否有来源支撑？ |
| 机制 | 是否存在跳步、反向因果、未说明的中间变量？ |
| 中间结果 | 能否稳定发生？是否依赖极端条件？ |
| 最终影响 | 是否覆盖题目主体？是否足够大、足够持久？ |
| 评价标准 | 从事实到「应该 / 有错 / 更好」是否补足规范桥梁？ |
| 辩题结论 | 结论是否就是辩题要求的命题？有没有偷偷换题？ |

任一环答不上来 → 这个论点要改，不能靠言辞盖过去。

## 三、原有四项检查（继续执行）

① **逻辑关系**：论点间构成逻辑关系（递进最好，并列可接受），不能是各自独立的四件事
② **真实性与支撑**：每论点有逻辑支撑且至少一条事实支撑（数据 / 案例 / 实证研究）
③ **逻辑链精简**：相邻节点必须真正构成因果 / 递进，整链控制在 4-6 个关键节点
④ **应对挑战**：设想对方最有力反驳，确认我方还有有效回应空间

## 四、谬误定位表

检查论证时使用，**必须写出具体哪一步不成立，不允许只报谬误名字**——评委要听见为什么推论不成立。

| 谬误 | 在本报告中的表现 |
|---|---|
| 以偏概全 | 用个例证明普遍命题 |
| 诉诸完美 | 要求对方方案彻底解决问题才成立 |
| 滑坡 | 从 A 直接推到极端后果 Z，跳过中间环节 |
| 强加因果 | 相关数据被写成因果关系 |
| 因果倒置 | 把结果当原因 |
| 稻草人 | 攻击的不是对方最强版本 |
| 偷换概念 | 同一关键词前后定义不一致 |
| 虚假两难 | 只给两个选项，隐去替代方案 |
| 循环论证 | 结论被塞进前提或定义 |
| 幸存者偏差 | 只统计成功者，忽略失败样本 |

## 五、自检产出

自检属于工作信息，**写进报告附录，不写进正文**。附录格式：

```text
自检记录（A1-A3）
A1：六环 ✓ ；谬误定位：无
A2：六环 ✓ ；机制环曾缺「中间结果」，已补 X 数据
A3：六环 ✗（评价标准缺规范桥梁）→ 已重写收束段
```
