# 证据搜集与核验协议

> 方法框架整理自 hellobiyue/debate-prep-workbench（MIT）与 athena-caixinying/debate-prep（MIT）。

## 一、证据状态（每条资料必须标一种）

| 状态 | 含义 | 能否作核心证据 |
|---|---|---|
| 已核验 | 打开具体原文页，关键事实与元数据逐项一致 | 可以 |
| 部分核验 | 只能确认摘要或部分事实，细节无法访问 | 谨慎使用并披露限制 |
| 未核验 | 仅见搜索摘要、二手转述或页面打不开 | 不可以 |
| 来源冲突 | 可靠来源之间数据或定义不一致 | 先呈现冲突并解释取舍 |

正文中凡未达「已核验」的精确数字、法律、政策、时效性事实，一律标 `【待核验】`，**不得包装成事实**。
**链接存在 ≠ 内容已核验；HTTP 200 ≠ 页面内容匹配。**

## 二、来源优先级

1. 法律、政府统计、监管文件、法院文书、国际组织原始数据
2. 同行评审原始研究（有 DOI / 期刊可查）
3. 权威机构报告（大学、研究机构、行业协会）
4. 可靠新闻的事实报道（新华社、人民网等）
5. 二手评论、分析文章
6. 案例与轶事（**只能说明机制或作反例，不能单独证明普遍趋势**）

来源权威不等于推论有效，仍需检查样本、口径和相关性。

## 三、数据七查

| 检查 | 问题 |
|---|---|
| 时间 | 数据是否适用于辩题指定时期？ |
| 空间 | 其他国家、地区或群体能否外推？ |
| 样本 | 抽样是否代表讨论主体？ |
| 指标 | 测量的是否真是需要证明的概念？ |
| 基线 | 比例高低是否有历史或横向参照？ |
| 因果 | 相关性是否被误写成因果？ |
| 量级 | 即使方向成立，影响是否足以改变胜负？ |

## 四、搜索计划与覆盖基线

围绕每个核心交锋点 / 论点至少设计**四类查询**：

1. **直接查询**：主张、对象、关键指标
2. **权威来源查询**：政府、国际组织、大学、期刊、法院、行业机构；正式来源查询应带 `site:`、`filetype:pdf`、作者、DOI、`study`、`journal`、`report` 等质量限定之一
3. **反向查询**：批评、失败、无效、副作用、反例（**这条最容易漏，也最喂第 6、8 节**）
4. **语言与地区扩展**：中文与英文，以及辩题适用地区

覆盖数量按档位执行（见 SKILL.md「篇幅档位」），由任务风险和可用资料决定，**不为凑条数降低质量**。

每次查询记录：对应论点 / 交锋点编号、查询词、语言、目的（直接/权威/反向/扩展）、发现方式（直接搜索 / 引用链追踪）、结果条数。

## 五、链接治理

- 优先政府官网、权威媒体的稳定网页；不用地方小站、自媒体、短链
- **每个链接实际打开验证**（能打开且是目标内容即可，不必通读全文）
- 打不开的就地换成同源或同内容的可访问链接
- 403 / 405 / 429 属于「反爬拦截」，标记为可疑而非直接判死；其他 4xx / 5xx 与超时视为打不开

## 六、免费数据库（补充发现）

- **Crossref**：论文、DOI、作者、出版年份、出版社元数据
- **OpenAlex**：学术作品、作者、来源、开放获取、引用计数
- **World Bank**：按国家、年份、指标代码读取国际发展数据

数据库返回的是候选或元数据；**结论仍需打开摘要或全文**，World Bank 数据须保留指标代码、国家、年份和口径。

## 七、论证链检查

把论证改写为：`事实前提 → 机制 → 中间结果 → 最终影响 → 评价标准 → 辩题结论`。

逐环检查：

- 前提是否真实且合题？
- 机制是否存在跳步或反向因果？
- 中间结果能否稳定发生？
- 影响是否覆盖题目主体？
- 影响是否足够大、足够持久？
- 从事实到「应该 / 有错 / 更好」是否补足规范桥梁？
- 比较辩是否真正比较了对方最强版本？

## 八、表达规则

采用「准确复述 → 承认合理部分 → 指出不能推出之处 → 回到比较标准」的温和反驳结构。
避免用「荒谬」「毒瘤」「显然」等强烈词语替代证明；需要强结时，说明对方缺失的前提或证据，而不是只宣布其失败。
