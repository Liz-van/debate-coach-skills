# $立论 — 辩论备赛资料生成器

收到 `$立论` 时加载本 skill。生成内容使用 `deepseek-flash`，思考模式设为最高（max）。

## 输入格式

```
$立论 <辩题> <持方> [题解] [立论方向] [对抗轮数]
```

- **辩题**（必填）：辩论赛题目
- **持方**（必填）：正方 / 反方
- **题解**（可选）：题解原文；没有题解时用户会简述对题目的理解
- **立论方向**（可选）：用户对论一、论二的初步想法。用户可能同时给出两方立论并标注，**真正持方一律以持方参数为准**
- **对抗轮数**（可选）：双 Agent 对抗跑几轮；未写则按档位默认（见「篇幅档位」）
- **【讨论】**（可选、随时）：用户在任意消息里标 `【讨论】` 时，围绕他这条质疑追加一轮正反方对抗，只改受影响章节（见「讨论轨」）；**没标标记的疑问不开对抗**

## 交互规则

- 不使用选项卡片设计
- 对任何不确定的信息，**停下来询问用户**（可以有多次询问——每次选择可能带来更多问题）
- 不主动询问题解 / 立论方向——用户有会直接输入，缺失即跳过
- 开工前确认一次**交付档位**（精简 / 标准 / 完整）；用户当前消息已指定则跳过，未指定按「标准」
- 对抗轮数不单独问，随档位默认；用户明确写了轮数才用他的
- **【讨论】是唯一开关**：只有用户明确标了 `【讨论】` 才追加对抗轮；助手不许自行发起（其余疑问直接答、直接改稿）

## 工作流

### 第一步：辩题诊断（不得跳过，不直接进交锋点）

读 `references/motion-diagnosis.md`，先输出**辩题诊断卡**：主/次命题类型、论证结构、主体与场域时间、关键词最低证明标准、**双方举证责任分配**、决胜比较点、主要歧义与风险、当前采用的读法。

后面的判准从这里推出，论点义务按它分配，反驳按它打——诊断卡是整份报告的根。

### 第二步：资料查询（交锋点驱动 + 覆盖基线 + 核验）

读 `references/evidence-protocol.md`。执行要点：

1. 先按诊断卡列出**双方可能的事实争议点**，再针对每个交锋点定向搜数据
2. 每个核心交锋点至少 4 类查询：直接查询 / 权威来源查询（`site:`、`filetype:pdf`、作者、DOI）/ **反向查询（批评·失败·无效·副作用·反例）** / 语言与地区扩展
3. 覆盖基线按档位（见「篇幅档位」表）；用户未指定档位时先复述默认值再开工
4. 每条资料标注**证据状态**：已核验 / 部分核验 / 未核验 / 来源冲突；未核验内容正文标 `【待核验】`
5. 遵守来源优先级与「数据七查」；**链接能打开 ≠ 内容已核验**
6. 双方都分要素/领域/大类呈现，**不偏向某方**；补「相同环境与条件下、不同选择导致不同结果」的归因对照资料
7. 每条资料标真实来源（脚注）+ **绝对年份**，区分「当年情境」与「当下语境」

搜索途径（按优先级，可随时补充）：web_search → web_fetch 抓搜索引擎（Bing 中文优先，备选 DuckDuckGo；Google/百度可能被拦）→ web_fetch 直接抓知识源（百科、知名机构公开报告）→ 模型自身知识（明确标注局限）。

查询方向按辩题类型（历史 / 政策 / 价值 / 现象）见 reference。

### 第三步：论点草案与自检（草案版）

读 `references/argument-chain.md`。这一步产出的是**交给对手打的靶子**，先求论证链完整，不追求成稿文笔。**论点固定 3 个**（三档一致：精简 / 标准 / 完整都写 3 个，档位只改证据密度与对抗轮数，不改论点个数），每个论点三段式：**逻辑链预览**（箭头链一句话讲完整条论证路径）→ **展开叙述**（理论 + 事实论据 + 引用出处，语言有「辩感」）→ **收束**（自然上升到辩题价值层面，不另起「升华点」标签）。

草案必须逐条执行首轮自检：

- **论证链六环自检**：`事实前提 → 机制 → 中间结果 → 最终影响 → 评价标准 → 辩题结论`，逐环打勾
- **谬误定位**：以偏概全 / 诉诸完美 / 滑坡 / 强加因果 / 因果倒置 / 稻草人 / 偷换概念 / 虚假两难 / 循环论证 / 幸存者偏差——**必须写出具体哪一步不成立，不许只报谬误名字**
- **原有四项**：① 论点间构成逻辑关系（递进最好，并列可接受）② 每论点至少一条事实支撑 ③ 逻辑链控制在 4-6 个关键节点 ④ 每个环节都经得住对面最强版本的攻击——这一项由第四步的对手 agent 实际检验，**不写进正文**
- **语言自检**：对照下文「写作风格 → 去 AI 腔」清单逐条扫一遍（重点：宣传腔、「专家认为」这类模糊归因、句尾挂「凸显 / 体现」、排比凑三项）

任一不通过 → 重新调整后再往下走。

### 第四步：双 Agent 对抗收敛（不得跳过）

读 `references/adversarial-debate.md`。这一步默认执行，不是可选项：论点必须被**第二个 agent 站在对面**打过一轮以后，才算构造完成。单方想出来的论点自己看不出漏洞，这是本流程存在的全部理由。

1. **起两个 agent**（按优先级）：Agent Teams 的 `spawn_teammate` → `subagent` → Lead 分饰两角（兜底必须在报告附录标注）
   - **主笔 agent**：我方持方，维护论点体系，逐条回应攻击
   - **对手 agent**：对面持方，先 steelman 再用最强版本往死里打
   - 两个 agent 用**同一模型与同一思考等级**；否则模型差异会被误当成论证差距，裁决失去意义
2. **先锁四项再开打**：同一份诊断卡、同一套举证责任分配（只有方向相反）、同一批事实基准、同一档位
3. **回合制**：对手攻击（固定字段：目标论点 / 环节 / 谬误 / 严重程度 / 攻击主张 / 依据 / 最低修补要求）→ 主笔回应（修补 / 换证据 / 改判准 / 让步删点 / 拒绝并说明，并写清代价）→ 再攻……轮数按档位
4. **Lead 逐条裁决**：存活 / 修补后存活 / 降级为次要栏 / 删除，每条写理由。**删到少于 3 个就回第二步补料或改结构**（三档一致，论点固定 3 个），**不许硬凑**，也不许把删掉的论点换个名字塞回来
5. **红线**（违反即整轮作废）：不许编数据编来源；不许改我方持方；不许打稻草人；**立论正文不预判对方反驳**；不许虚构战果；不许两边放水
6. 对抗记录写 `~/.dsh/tmp/<任务名>/debate.json`（R6），跑 `check_debate.py`，硬项通过才往下走；用户标【讨论】后追加的讨论轮记进同一份 JSON 的 `discussion` 字段（H11–H14）

对抗的产物分三处落，**不许混**：

- 修补后仍然成立的论证 → **§4 持方论点体系**（只写我方主张，不带「对方会说……」）
- 对抗中真实的攻击与我方回应 → **§6 反方观点与反驳** 与 **§8 攻防预判**
- 轮次、攻击、裁决表、未闭合项（含讨论轨） → **报告附录·对抗收敛记录**

裁决后对存活论点**再跑一次六环自检**（终稿版），跟第三步的首轮自检记录对一遍，确认修补真的闭合了。

### 第五步：攻防构造

读 `references/attack-defense.md`。第四步对手 agent 打出来的攻击与判决陈述**直接喂这一节**——§6 的「对方最强版本」优先用真实的攻击原文，而不是凭空想象；§8 的攻防对话按对手实际追问链展开。这一步只做补全和成稿，不重开一轮对抗。

- **对方论证必须 steelman**：先用对方能认可的语言写出其最强合理版本，再拆解；不得妖魔化
- **反驳四步**：准确复述 → 指出争议在事实/机制/概念/比较/影响哪一层 → 给理由、反例或证据 → 说明这如何改变胜负比较
- **质询追问链**：每组预设对方「是 / 否 / 回避 / 反问」四种回答的下一步，准备**退出句**；小结只写场上实际拿到的承认，不虚构战果
- **可控靶点**（可选）：引对方进入我方准备充分的争议；**红线**——不得留假数据、偷换概念或误导性省略

### 第六步：生成交付物

1. **创建文件夹**：`~/debate/备赛/<辩题文件夹>/`
   - 文件夹名 = 辩题去掉「/」与另一持方表述，**只保留我方持方全称**
   - **同一辩题两方合并（重要）**：备赛目录下已存在同一辩题的相反持方文件夹时**不新建**，改为合并进**中性辩题文件夹**（去掉持方分歧表述、保留共同主干，惯用「是否」句式），内部分「正方」「反方」子文件夹，各自存该持方的 md 与 xlsx（文件名保留持方全称）；合并后删除原持方文件夹（**删除前先列清单二次确认**）
2. **生成两个文件**（文件名 = 文件夹名）：`<辩题>.md`、`<辩题>.xlsx`
3. **先跑两项预检，再出文件**：
   - 对抗记录：`...\scripts\check_debate.py <debate.json> --md <报告.md> --tier <档位>`（轮数、攻击环节、修补、裁决、§4 纯净）
   - 资料数据：`...\scripts\precheck.py <数据.json> --md <报告.md> --tier <档位>`（覆盖不足 / 来源编号重复或缺失 / 链接打不开）
   
   任一硬项不通过先修再出
4. **md 转 PDF 并发微信**（PDF 生成在 `~/.dsh/tmp/`，文件本身留在 备赛工作目录）
5. **临时文件一律不留在交付文件夹（硬规则）**：脚本、中间数据 JSON（含 `debate.json`）、HTML 中间产物、截图、转码副本、日志等，全部写到交付文件夹之外，**统一落在 `~/.dsh/tmp/`**（全局 R6；不要在 `~/debate/` 下建 `.tmp\`、`.tools\` 之类的工作目录），用完即删；`_` 开头的中间文件同样不许留在交付文件夹里。交付前逐项核对，**交付文件夹内只应有该持方的 `<辩题>.md`、`<辩题>.xlsx`（以及同名 PDF）**，多一个都算没交付完。发现残留：先列清单 → 用户确认 → 删除（R2）

脚本：

```bash
python ~/.dsh/skills/argument-construction/scripts/check_debate.py <debate.json> [--md <报告.md>] [--tier 标准]
python ~/.dsh/skills/argument-construction/scripts/precheck.py <数据.json> [--md <报告.md>] [--tier 标准] [--no-link-check]
python ~/.dsh/skills/argument-construction/scripts/generate_report.py xlsx <输出.xlsx> <数据.json>
python ~/.dsh/skills/argument-construction/scripts/generate_report.py pdf  <输入.md> <输出.pdf>
```

数据 JSON 结构见 `scripts/generate_report.py` 顶部注释；对抗记录 JSON 结构见 `references/adversarial-debate.md` 第八节，讨论轨见第九节。

## 讨论轨（【讨论】触发的追加对抗轮）

**唯一开关**：用户消息里出现标记词 `【讨论】`。没出现 → 他的疑问走普通对话（直接答、直接改稿），**不开对抗**；助手不许自己判断该不该再打一轮。触发后**重新站边**：正反两个 agent 围绕**他这一条质疑**再打一轮，打完只改受影响的章节。

一轮讨论 = 一条追加对抗轮：

1. **锁定靶心**：把他的质疑/方向当成本轮唯一议题（记进 `discussion[].trigger`），不许顺手重打别的论点，也不许重跑首轮对抗
2. **重新站边**：优先用 `send_message` 把新任务派给同一对 agent（主笔仍我方、对手仍对面，同一个 agent 不许换边）；agent 不可用就按第四步的优先级重起，兜底照旧标 `fallback: true`
3. **攻防 + 裁决**：对手只围绕靶心出最强攻击（字段同第四步）→ 主笔逐条回应 → Lead 逐条判 **成立 / 不成立**，判「不成立」必须写理由；**靶心本身站不住就直说**，不许为了顺从用户而假装它成立
4. **只改受影响章节**：改 `§4` / `§6` / `§8` / 附录对抗记录里的**相关部分**，逐项写进 `changed[]`（哪一节、哪个编号、改了什么）；**不许借讨论轮重写全篇**，也不许改与靶心无关的内容
5. **不占档位轮数**：档位 1/2/3 轮是首轮收敛的预算，讨论轮是追加——不放宽首轮下限，也不会因为「没有讨论轮」而免掉那些检查；讨论轮自己跑 `check_debate.py` 的 H11–H14
6. **重跑校验**：改完重跑 `check_debate.py`（md 改了带 `--md`），硬项通过才交新版；封面版本说明加一行「第 n 轮讨论：靶心 → 改了什么」
7. 讨论轮改了论点结局 → 同步更新顶层 `verdicts`（H8/H9 以顶层为准）；删到少于 3 个论点照样回炉补料

一条消息里多个质疑 → 按顺序拆成多条讨论轮（`n` 递增），每轮只打一个靶心；默认一条靶心一轮，不自动追加。

## 交付物一：深度调查报告（Markdown）

版块顺序固定（0-11）。**编号体系全报告打通**：论点 `A1`、交锋点 `F1`、对方路线 `O1`、证据 `E1`、攻防模块 `B1`；来源统一编号并与 xlsx 一致，正文引用写 `[5]` 或 `[5,7,8]`。

0. 封面（辩题 / 持方 / 制作日期 / 交付档位 / 版本说明）
1. 辩题诊断卡 + 由它推出的判准建议（说明为什么该判准有利于我方）
2. 辩题拆解：三层交锋表（事实层 / 价值层 / 身份层：核心问题 + 双方必争）
3. 概念界定（可选）
4. 持方论点体系（**只写我方主张**；不带「对方会说……」——立论不预判反驳）
5. 核心对象原型资料
6. 反方观点与反驳（对方最强版本 + 反驳四步）
7. 事实交锋点
8. 攻防预判
9. 质询与结辩建议
10. 论点资料区
11. 来源索引

**主稿纯净规则**：问题地图、搜索诊断、核验限制、待补资料、配置状态、自检记录、**对抗收敛记录**（轮次 / 攻击 / 修补 / 裁决表 / 未闭合项 / 讨论轨，含「本轮由单 Agent 分饰」这类兜底标注）属于工作信息，只进报告附录或聊天说明，**不得混入正文**。

**排版要求（第 8 节，必须遵守）**：每组攻防之间空一行；组内每一句独立成段（「对方可能打」标题、对方说、我方回、对方追问、我方再回各自单独一行，行间空一行）；禁止连写成一大段。

各版块详细写法见 `references/report-sections.md`。

## 交付物二：资料表（Excel）

Sheet 顺序固定：封面 / 辩题诊断卡 / 核心对象原型资料 / 反方观点与反驳 / 事实交锋点 / 来源索引 / 概念界定（可选）/ 论点一、论点二……（每个论点一个 sheet）。

文字性板块（判准、论点论述、攻防预判、质询结辩建议）**只进 md，不进 Excel**。新增两列：**证据状态**、**来源类型**（官方统计 / 学术 / 机构报告 / 权威媒体 / 案例）。

数据规范：

1. 每条资料必须带来源；有「来源」列只填缩写编号（`[5]` 或 `[5,7,8]`）；无来源列的文字内容句末标 `[来源X]`，话题外用到其他来源时句末补标
2. 每条可溯源：「一句话结论」（主语 + 数字 + 趋势，脱离原文可独立成立）与「核心内容」（出处 + 年份 + 统计主体 + 关键数字 + 口径）；关键数字必须带年份、统计主体、口径三件套；提炼不出独立成立结论的来源直接弃用
3. 纯资料表，不用「辩称」等战斗化措辞
4. 同类去重，保留数据最直接、来源最权威的一条
5. 个例适度：个体案例与群体现像搭配，剔除过于奇绝、易被质疑「幸存者偏差」的个例
6. 链接治理：优先政府官网、新华社/人民网等权威媒体的稳定网页，不用地方小站、自媒体、短链；**每个链接实际打开验证**，打不开的就地换成同源或同内容的可访问链接
7. 时间注明绝对年份或时间线，区分「当年」与「当下」
8. 修改时保持 sheet 结构与来源编号稳定，改完列改动清单并更新封面版本说明

格式规范（脚本已内置，AI 只填数据）见 `references/excel-spec.md`。

## 交付

- 通过消息工具发送 PDF（md 的打印版），无需额外确认
- md / xlsx 已存入 备赛工作目录；**交付文件夹内不留任何临时文件**（脚本、中间 JSON、HTML、截图、日志、`_` 前缀文件）
- 交付前把交付文件夹列一遍，确认只剩 md / xlsx（及同名 PDF）三个文件
- 搜索受限时写进**报告附录**，不写正文

## 写作风格

- 有辩论队备赛材料的质感，而非学术论文
- 短句、判断句为主，关键结论前置
- 引用只标出处名 + 年份，不需要完整引用格式
- 有「辩感」——能想象到辩手在赛场上会这么说
- 体现「预判反方 + 抢先拆解」的攻防意识
- 不用「荒谬」「毒瘤」「显然」等强烈词语替代证明；需要强结时指出对方缺失的前提或证据
- **语言要展开写，不许压缩成电报体（硬要求）**：论点段、判准、攻防理由都要把推理一步步写全——先说哪一句、为什么能推出下一句、例子在哪。宁可长一点，也不要有「结论＋术语」的跳步。用户明确反馈过：报告有些地方写得过于简练，读起来很累
- **用大白话，不拟人、不比喻**：不用「读数」「回执」「账」「形态」「装置」这类说法（用户点名要求避免）。抽象机制一律翻译成日常说法——不写「遗憾是这套心理装置正常运转的读数」，写「有遗憾，说明这个功能在工作」
- **术语第一次出现时用一句白话解释**，之后再用简称（例：「目的感——心理学里指一个人觉得自己这一辈子有方向、还想往前」）
- 「短句、判断句」与「展开写」不冲突：句子要短，但步骤不能省；一段只讲一件事
- 不过度解释常识性概念；心理学与统计术语不在此列，按上一条解释

### 去 AI 腔（源自 `deai-writer` skill 的 Language rules，已改写成中文辩论语境）

以下每条都是硬要求，完稿后逐条扫一遍再交付：

- **不给事实戴高帽**：不写「深刻体现了」「恰恰印证了」「具有里程碑意义」「标志着……的开端」「掀开了新的一页」。事实是什么就写什么，意义靠后面推理一步步推出来，不靠形容词宣布。
  - 反例：「这项政策深刻体现了国家对民生的重视。」正例：「这项政策把报销比例从 50% 提到 80%，说明财政愿意把钱花在这一块。」
- **句尾不挂「凸显 / 体现 / 折射 / 彰显」**：挂在句尾的这类短语是假深度。拆成独立句子，写清「谁做了什么 → 所以能推出什么」。
  - 反例：「补贴落地后参保率涨了三成，凸显了政策的有效性。」正例：「补贴落地后参保率涨了三成。这是政策起了作用的直接证据。」
- **不写「不仅……而且……」「这不只是……更是……」**：压成一句直接判断。
- **归因落到具体来源**：不写「专家认为」「有研究指出」「不少人觉得」「业内普遍认为」。要么点出谁、哪一年、什么机构、什么口径，要么整句删掉（与 `references/evidence-protocol.md` 的核验要求一致）。
- **宣传腔一律删**：「重磅」「令人瞩目」「意义深远」「堪称典范」「引人深思」「值得每一个人思考」。
- **AI 高频词换成实词**：「此外 / 与此同时」不是真并列就删；不堆抽象的「赋能」「抓手」「闭环」「生态」「维度」；「关键 / 至关重要 / 不可或缺 / 深刻」要有具体内容撑着，撑不住就删；「值得注意的是」直接删。
- **不回避「是」**：不写「作为……而存在」「扮演着……的角色」「构成了……的重要一环」，写「是」「有」「导致」。
- **不硬凑排比、不换词**：有几点写几点，不凑三项；同一个概念全文用同一个词，不换着说法叫；不用「从……到……」把不在一个尺度上的东西连起来。
- **标点与加粗**：破折号不滥用，用逗号或拆句；普通词语不加粗，加粗只留给首次出现的新术语；不写「挑战与展望」这类套路小标题。
- **改掉空洞的对冲和填充词**：「为了……的目的」→「为了」；「由于……这一事实」→「因为」；「在此时此刻」→「现在」；「有能力做到」→「能」；「需要指出的是」「不可否认」删掉；一句话里叠两三个限定词，留一个准确的就够了。
- **不留对话痕迹**：正文里不出现「希望这些内容对你有帮助」「当然」「你说得很有道理」「以下是……」，不出现助手口吻。
- **去 AI 腔 ≠ 写成一堆中立短句**：判断还是要下判断，长短句交替，读起来像辩手在说话，而不是像词条。

## 篇幅档位

| 档位 | 论点 | 准入证据 | 单论点证据 | 对抗轮数 | 适用 |
|---|---|---|---|---|---|
| 精简 | 3 | ≥6 | ≥2 | 1 | 快速摸底、临时补料 |
| 标准（默认） | 3 | ≥8 | ≥2 | 2 | 常规备赛 |
| 完整 | 3 | ≥12 | ≥3 | 3 | 正式比赛、资料密集辩题 |

**「论点」一列三档都是 3 个，固定不随档位变**：档位加的是证据密度与对抗轮数，不是论点个数（旧版「完整档 ≥4」已取消）。这 3 个是对抗裁决**后**仍存活（存活 / 修补后存活）的论点——打完不够 3 个，就回第二步补料或改结构，**不许硬凑**，也不许把删掉的论点换个名字塞回来；`check_debate.py` 的 H3b（草案登记）与 H9（裁决后存活）卡这一条。对手攻击总数下限为 2 / 3 / 5 条，且至少覆盖 1 / 2 / 2 个不同论点（详见 `references/adversarial-debate.md`）。**「对抗轮数」是首轮收敛的预算**：用户标【讨论】后追加的讨论轮不吃这个上限，也不放宽它——首轮该跑的轮数与攻击数下限一条都不少，讨论轮自己跑 H11–H14（见「讨论轨」）。

## 搜索不可用的处理

1. 先尝试备选搜索方式
2. 确认网络是否可达
3. 全部不可用则基于模型已有知识撰写，标注资料局限性
4. 在报告交付后附加搜索诊断说明（放附录）
