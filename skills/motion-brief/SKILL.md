# $评赛 — 辩题速览生成器

收到 `$评赛` 时加载本 skill。

## 输入格式

```
$评赛 <辩题> [题解] [赛制]
```

按空格切分解析：

- **辩题**（必填）：如「技术越发展，人越是/不是自己的主人」
- **题解**（可选）：题解原文；没有则跳过，不主动询问
- **赛制**（可选）：赛制/持方安排说明（如「奥瑞冈」「两人制」）；用户给了就参考，缺失即跳过

交互规则：不使用选项卡片设计；对不确定的信息停下来询问用户；缺失的可选输入不主动追问。

## 模型要求

- 全程使用**当前默认 flash 档模型**（deepseek/deepseek-v4-flash），**不得**切换到 pro 或更高思考档

## 内容边界（铁律，违反即返工）

1. 只做「帮助快速了解辩题」的中立速览：
   - ❌ 不针对任何一方做完整立论
   - ❌ 不联网检索、不引用外部资料与来源
   - ❌ 不做攻防预判（不写「对方可能怎么打、我方怎么回」）
2. **两方内容篇幅、力度、措辞必须均衡**；禁止「显然/站不住/更合理/碾压」等倾向判断
3. 不编造具体数据、统计、案例出处；只基于题目文本与模型常识做**框架性**描述；事实层只写「双方会争论哪类事实」，不写具体数字
4. 板块标题与顺序固定（0–6），内容以「让没接触过辩题的人五分钟看懂在争什么」为目标

## 工作流

1. 解析输入
2. 按下方「板块结构」撰写 Markdown（语言：短句、判断句、可直接扫读）
3. 存 md：`~/debate/评赛/<辩题>.md`（即`~/debate/评赛/`）
   - 直接放在评赛目录下，**不建子文件夹**；文件名 = 辩题
   - 去除 Windows 非法字符 `\ / : * ? " < > |`
   - 辩题含持方表述（「A 是/不是 B」）时，中性化为「A 是否是 B」作文件名（如「技术越发展，人是否是自己的主人」）
4. 转 PDF 并发微信：
   ```bash
   python ~/.dsh/skills/motion-brief/scripts/md2pdf.py <输入.md> <输出.pdf>
   ```
   PDF 生成在 `~/.dsh/tmp/`（全局 R6），通过消息工具发送；**PDF 不落盘 交付文件夹**，md 文件留在 `~/debate/评赛/`
5. 交付：PDF 直接发送，无需额外确认

## 板块结构（0–6，顺序固定）

### 0. 封面速览
辩题原文；辩题类型（价值 / 事实 / 政策 / 混合，附一句判断理由）；一句话背景（这题在讨论什么议题）；制作日期。

### 1. 辩题拆解
- **核心概念中性口径**（列表）：概念 | 正方可能界定 | 反方可能界定 | 争议所在——只罗列口径，不下对错判断
- **比较结构**：比较主体、比较对象、时间/范围维度；双方默认口径与反方可能的切割各写一句，中立呈现

### 2. 双方思路骨架
- 正方核心逻辑链：2–3 句，箭头短句讲清一条主线
- 反方核心逻辑链：2–3 句，同上
- 仅骨架级，明确不展开为完整立论；两方篇幅相当

### 3. 可能的争论焦点
概念层 / 事实层 / 价值层各列 1–2 个焦点，每焦点一句式：「正方倾向……反方倾向……焦点在……」；事实层只写争论哪类事实，不给数据。

### 4. 观赛指南（评赛视角，中立）
- 通用观赛检查点：定义是否可操作、论据是否与论点同层、是否正面回应对方核心主张、价值收束是否完整
- 常见判准思路罗列（论点完成度 / 交锋回应 / 价值收束等），不指定任何一方该赢

### 5. 常见误区
3–5 条观众/新手对这类辩题的常见理解偏差（常识层，不查资料）。

### 6. 适用场景速查
论域一句话；可用类比或思考框架一句带过（不展开、不论证）。

## 中立自检（交付前逐条执行）

- [ ] 两方描述篇幅与力度均衡
- [ ] 无「显然 / 更合理 / 站不住」等倾向措辞
- [ ] 无编造的数据、统计与来源
- [ ] 无攻防预判句式
- [ ] 不确定处均用「可能 / 倾向」等中性词
