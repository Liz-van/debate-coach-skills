# 双持方赛制辩论 — 九人队伍

本 skill 的前提是 **已有可用的 Agent Teams 工具**（`spawn_teammate` / `send_message` / `wait_agent` / `list_agents` / `team_task_*`）。起人前先确认这些工具在；不在就走本文末尾的降级路线。

**借用与自有**：立论报告的版块与写作风格、诊断卡与资料协议、以及 `precheck.py` / `generate_report.py` 全部沿用 `~/.dsh/skills/argument-construction/`（本文里的 `references\...` 若写明全路径就是那边的文件）；本 skill 自有的只有这个 `SKILL.md`、`references\match-record.md`、以及 `scripts\` 下的 `check_match.py` / `count_speech.py` / `speech_bands.py`。

## 什么时候用本 skill

- 收到 `$立论 <辩题>` 且**用户没有注明持方** → 走本 skill，正反两方都出。
- 用户**注明了持方** → 不走本 skill，走 `argument-construction` 的单持方流程（原 `$立论` 行为不变）。

本 skill **不发 PDF**，也**不卡报告字数**（报告字数只在正文里写明、脚本默认只告警，加 `--strict-words` 才当头拦）。

**但立论类稿的字数是硬项**：每个环节对应多少字由时长换算出来，辩手**发言前必须自查**，超区间不许上场；质询与自由辩论不卡稿子，改卡**每方实际发言总量**（见「发言字数：照时长卡」）。

## 输入格式

```
$立论 <辩题> [题解] [立论方向]
```

- **辩题**（必填）：辩论赛题目
- **题解**（可选）：题解原文；没有就跳过，不追问
- **立论方向**（可选）：用户对两方论点的初步想法，可能同时给双方并标注；**只是参考，两方各自的立论仍由本方辩手写**

## 开工前确认（只确认这一项）

**交付档位：精简 / 标准 / 完整**。用户当前消息已指定就跳过；没写按「标准」。

| 档位 | 场次 | 每方立论报告字数 | 说明 |
|---|---|---|---|
| 精简 | 2 场 | ≥ 2 万字 | 快速摸底 |
| 标准（默认） | 3 场 | ≥ 3.5 万字 | 常规备赛 |
| 完整 | 4 场 | ≥ 5 万字 | 正式比赛、资料密集辩题 |

- **字数口径**：去掉全部空白字符后的字符数（含标点），正反两方**各算各的**，各自都要达标。
- **辩手资料（稿子）不计入字数**：稿子是上台念的口语稿，报告是备赛分析稿，两套东西分工不同。
- 场次是**上限**：双方都报告「无修改」时可以提前收场（见「场间修改」）。
- 论点一方 3 个，三档都一样，固定不随档位变。

交互规则：不用选项卡片；不确定就停下来问（可以有多次询问）；不主动询问题解 / 立论方向。

## 团队编制：11 个 teammate

用 `spawn_teammate` 一次起齐 11 个，**全程复用，不中途重起**（重起会丢上下文）。11 个人用**同一模型、同一思考等级**（`deepseek-flash`，思考等级最高）。

| 名字（spawn 用） | 角色 | 职责 |
|---|---|---|
| `zheng-1` | 正方一辩 | 本方论点主笔，写立论稿；场上第一个开口 |
| `zheng-2` | 正方二辩 | 写申论稿；被质询时答辩 |
| `zheng-3` | 正方三辩 | 写质询稿与小结稿；质询对方二辩 |
| `zheng-4` | 正方四辩 | 写结辩稿；质询对方一辩；自由辩主攻 |
| `zheng-data` | 正方资料员 | 只查资料，不写立论；产出本方 `资料.xlsx` 的底稿与来源编号 |
| `fan-1` … `fan-4`、`fan-data` | 反方同上 | 同上 |
| `judge` | 评委 | 判准、投票、逐条论点提修改要求；**自己不写立论、不替任何一方补论证** |

**Lead（我）是主席**，不是辩手，也不下场评议：主持赛程、锁共同基准、派活收活、汇总交付。主席不许替任何一方补论证，也不许虚构战果。

起人时给每个人一条共享任务卡（`team_task_create` + 认领），写清：角色、要交的文件路径、什么时候交。**写文件的路径不许重叠**——正方写 `正方\`，反方写 `反方\`，实录只有主席写。

**降级路线**（Agent Teams 起不来时，按顺序降）：`spawn_teammate` → `subagent` → Lead 分饰。降到第二、第三档时必须在《辩论实录》附录里标 `fallback: true`，并写明哪些角色是同一个 agent 扮的。

## 赛制：一场 13 个发言单元

标准四对四交叉赛制，按这个顺序跑，**顺序和时长不许改**：

| # | 环节 | 方 | 谁 | 时长 | 口径与字数 |
|---|---|---|---|---|---|
| 1 | 一辩立论 | 正方 | 正方一辩 | 3 min（180 s） | 立论正文 700–860 |
| 2 | 四质询一 | 反方 | 反方四辩质询正方一辩 | 1.5 min（90 s） | 按每方总量卡 175–215 |
| 3 | 一辩立论 | 反方 | 反方一辩 | 3 min（180 s） | 立论正文 700–860 |
| 4 | 四质询一 | 正方 | 正方四辩质询反方一辩 | 1.5 min（90 s） | 按每方总量卡 175–215 |
| 5 | 二辩申论 | 正方 | 正方二辩 | 2 min（120 s） | 申论正文 470–570 |
| 6 | 三质询二 | 反方 | 反方三辩质询正方二辩 | 1.5 min（90 s） | 按每方总量卡 175–215 |
| 7 | 二辩申论 | 反方 | 反方二辩 | 2 min（120 s） | 申论正文 470–570 |
| 8 | 三质询二 | 正方 | 正方三辩质询反方二辩 | 1.5 min（90 s） | 按每方总量卡 175–215 |
| 9 | 三辩小结 | 正方 | 正方三辩 | 2 min（120 s） | 整份 470–570 |
| 10 | 三辩小结 | 反方 | 反方三辩 | 2 min（120 s） | 整份 470–570 |
| 11 | 自由辩论 | 双方 | 四个辩手轮转抢话 | **各 4 min（每方 240 s）** | 按每方总量卡 940–1140（单个时间片 20–40 s ≈ 80–190 字） |
| 12 | 结辩 | 反方 | 反方四辩 | 3 min（180 s） | 结辩正文 700–860 |
| 13 | 结辩 | 正方 | 正方四辩 | 3 min（180 s） | 结辩正文 700–860 |

**自由辩论按时间片轮转**：4 对 4 共享一块发言板，不是各说各话。一方说完立刻换另一方，同一个辩手不许连着说两次；每个时间片写清「谁、说了多久、打的哪一点」，谁没有可说的可以被跳过，但要记下来。**质询也一样，允许短攻防**：问一句、对方答完、你再追一句，随时照对方的回答改口径，不必事先把话写死。

## 发言字数：照时长卡

时长不是写在纸上的数字，是**能念多少字**。基准语速 **260 字/分钟**，区间 = 中心值 ±10%，取整到 10；口径是**去掉全部空白字符后的字符数（含标点）**，和立论报告同一套算法。

**两类稿子，两种管法。**

**一、立论类稿（要写成逐字稿，上台照着念）——只量属于它自己的那一段**：

| 稿子 | 只数哪一段 | 区间 |
|---|---|---|
| `一辩立论稿.md` | `## 立论` | 700–860 |
| `二辩申论稿.md` | `## 申论` | 470–570 |
| `三辩小结稿.md` | 整份（它没有别的段落） | 470–570 |
| `四辩结辩稿.md` | `## 结辩` | 700–860 |

**`## 被质询时的答话`、`## 质询` 这些段落一律不算进区间**——那些是现场应对，事先写满会挤掉立论的时间预算，还会让人误以为「立论已经写够了」。

**二、要点类稿（只写弹药，不写台词）——不卡字数**：`三辩质询稿.md`、`自由辩要点.md` 想写多少写多少，只在超上限 3 倍时提示一句「写成了逐字稿」。

**区间内的不管**：落在区间里就算过，不要求卡到中心值。**低于下限**说明时间没用满，**高于上限**说明按这个语速念不完。

**质询与自由辩论：卡一方实际说了多少，不卡某一句话。**

- **质询**（`四质询一` / `三质询二`）：进实录的是**每方实际发言总量 175–215 字**——拿 90 秒里的一半时间说话。问方、答方各算各的。场上短攻防照打，实录可以按回合记（每次发言带 `words`，标 `问` / `答`），脚本会按方自动汇总；也可以直接记该段总字数。
- **自由辩论**：进实录的是**每方实际发言总量 940–1140 字**（4 分钟）。按时间片轮转，接不上可以被跳过，实录记每方总量。

**每位辩手在输出发言前必须自查**，把立论类稿交给脚本量一遍：

```bash
python count_speech.py <草稿.md> --unit <环节>            # <环节> 取 一辩立论/二辩申论/三辩小结/结辩
python count_speech.py <草稿.md> --unit 四质询一 --part 质询  # 想单看某节（例：四辩结辩稿的「质询」节）
python count_speech.py <草稿.md> --seconds 150           # 自定义时长
python count_speech.py --list                            # 打印全部区间
python count_speech.py --dir <某方>\辩手资料               # 一次量完本方立论类稿，顺手提示要点类稿
```

- 出区间就**改稿再发言**，不许先发出去再补。`--dir` 自查是主席收活时的门禁。
- 实录里每段发言要记 `words`；**没记的走 S9 告警**（质询逐回合记 `words` 也算记了），记了但出区间的走 **H15 硬项**。
- 交付时**四份立论类稿**按 **H16 硬项**核对；**要点类稿只提示**，超上限 3 倍才算 **S10 告警**。
- 稿子挂哪个环节：`一辩立论稿`→一辩立论；`二辩申论稿`→二辩申论；`三辩小结稿`→三辩小结；`四辩结辩稿`→结辩；`三辩质询稿`、`自由辩要点`→要点类不卡；`数据资料.md` 不卡（它是对照用的资料摘要，不是上台念的稿）。

## 每一场怎么推进

### 第 0 步：锁共同基准（只在第一场前做一次，之后每场赛前复核）

对抗的前提是两方站在同一块地基上。主席做四件事：

1. **辩题诊断卡**：读 `~/.dsh/skills/argument-construction/references/motion-diagnosis.md`，主席起草诊断卡（主/次命题类型、论证结构、主体与场域时间、关键词最低证明标准、**双方举证责任分配**、决胜比较点、主要歧义与风险、当前采用的读法）。
2. **双方一辩各提修改意见**，主席据意见定稿。诊断卡一旦锁定，后面所有判准、举证义务、反驳都从它推出来。
3. **评委过目确认**（只判「能不能用」，不写内容）——诊断卡是判准的根，评委要认这份卡才判得下去。
4. **事实基准**：两名资料员的来源**合并成同一批可用事实**（同一批事实双方都能引，但**两方的来源编号互不通用**：正方编号只在本方报告里有效）。有冲突的来源当场标出来，不许两边各用各的。

### 第 1 步：资料查询

两名资料员**各查自己的持方**，照 `~/.dsh/skills/argument-construction/references/evidence-protocol.md` 走：每个交锋点至少 4 类查询（直接 / 权威来源 / 反向 / 语言与地区扩展），每条标**证据状态**（已核验 / 部分核验 / 未核验 / 来源冲突）。

产出：`正方\资料.xlsx` 底稿（数据 JSON，脚本生成）与 `反方\资料.xlsx` 底稿。资料员不写论点、不替辩论方站台。

### 第 2 步：论点草案登记

每方 **3 个论点**，由该方一辩主笔，二三四辩各自给意见。每个论点三段式（照 `~/.dsh/skills/argument-construction/references/argument-chain.md`）：逻辑链预览（箭头链）→ 展开叙述 → 收束。草案要点登记进实录的**草案登记表**，编号 `A1` / `A2` / `A3`（每方各一套，在自己的报告里编号）。

草案过一遍六环自检：`事实前提 → 机制 → 中间结果 → 最终影响 → 评价标准 → 辩题结论`。

### 第 3 步：跑完 13 个发言单元

按上面的表逐个跑。每个单元：

- **发言前先自查字数**（`count_speech.py --unit <环节>`，上限/下限都要落区间内），出区间就改稿，改完才发言；
- 发言的辩手把内容写进**辩手资料**里对应的稿子（`一辩立论稿.md` / `二辩申论稿.md` / `三辩质询稿.md` / `三辩小结稿.md` / `四辩结辩稿.md` / `自由辩要点.md`）；
- 同时给实录交一份**要点摘要**（一两句话，不是全文台词）与该段的**字数** `words`，主席登记进对局记录。
- **字数怎么记**：立论、申论、小结、结辩这些逐字稿环节，`words` 就是那份稿子的字数；**质询和自由辩论改成记「每方实际说了多少」**——可以按回合记（每次发言带 `words`，标 `问` / `答`），脚本会自动按方汇总，也可以直接记该段每方的总量。

质询和自由辩论**照现场打，不要事先把话写死**：对方答完你再决定追哪一句。

质询环节的弹药库（`三辩质询稿.md`）要写**追问链**：每组预设对方「是 / 否 / 回避 / 反问」四种回答的下一步，准备退出句。小结只写场上实际拿到的承认，**不虚构战果**。

### 第 4 步：评委裁决

评委按下面的判法出结果。**评委不写立论**，也不替任何一方补论证。

### 第 5 步：场间修改

一场的裁决全部落定后，才进修改。见「场间修改」一节。

### 第 6 步：下一场

**双方都报告完成之后**，才开下一场。下一场从第 3 步重新跑（第 0 步的共同基准赛前复核一次，有变化才改）。

## 评委怎么判

读 `~/.dsh/skills/argument-construction/references/motion-diagnosis.md` 里判准的写法。评委每一场出四样东西：

**① 技术票：7 张，每个环节 1 张。** 环节就是 一辩立论 / 四质询一 / 二辩申论 / 三质询二 / 三辩小结 / 自由辩论 / 结辩。每张票投给「这个环节谁做得更好」的一方，并且**逐层给三层的判断**：

- **事实层**：谁的事实更站得住、举证责任谁尽到了
- **价值层**：谁的判准更能解决这道题、谁的比较点更有分量
- **身份层**：谁的立场更自洽、更像这道题里该有的样子

三层各写「正方 / 反方 / 打平」，票投给整体占优的一方，写清为什么。

**② 印象票：1 张。** 投给整体观感更好的一方。

**③ 战场总结。** 这场到底在争什么、哪条线被破了、哪条线守住了；**点出双方得失**——每方各写「做得好的」和「没做好的」。

**④ 逐条论点的问题清单 + 最低修补要求。** 双方各 3 个论点，**6 条都要覆盖**：哪一环不闭合、错在哪、最低要求改到什么程度才算过关。这个论点这轮确实没问题，就明确写「无」，修补要求写「保持」。

**计分**：每张票 1 分，一场共 8 分（7 技术 + 1 印象），多场**累计**。计分表只进《辩论实录》，不进 xlsx。

**裁决标准（沿用对抗裁决的老规矩）**：一条批评成立要同时满足三条——①说得出是哪一环不闭合；②带依据（`[n]` 来源或「逻辑反驳：……」，写明逻辑上哪一步不成立）；③最低修补要求是我方能做到的（要求「彻底解决」「保证没人质疑」属诉诸完美，判不成立）。每条批评只打一个环节。

评委的红线：不许编数据编来源；不许因为「整体印象」就放过具体错误；不许虚构场上没出现的交锋；不许两边放水。

## 场间修改

- 场上发现的问题**在该场比赛全部跑完之后才改**，边打边改是违规的。
- 每方由本方一辩牵头报告：**「有修改」或「无修改」**。
  - **有修改**：列出要改的论点编号（`A1`/`A2`/`A3`）、动作（修补 / 换证据 / 改判准 / 让步删点 / 拒绝并说明）、具体怎么改、代价（没让步写「无」）。改完要重跑六环自检，确认真的闭合了。
  - **无修改**：写清理由（为什么评委提的问题这一轮不需要动），并且**一条修补都不许带**。
- 场间可以让几个辩手 agent **讨论**（只讨论怎么改，不重打整场），并且**让资料员做资料补充**：补进来的来源要接着原有编号往下编，登记进实录。
- **提前收场**：双方都报告「无修改」时，逐轮优化到此为止，不必打满档位场次。清单里记下提前收场的场次和原因。
- 论点改到少于 3 个（含删除）→ **回炉补料或改结构**，不许硬凑，也不许把删掉的论点换个名字塞回来。每场结束时每方必须仍然是 3 个存活（存活 / 修补后存活）的论点。

## 立论报告怎么写

版块、编号、写作风格**全部沿用 `argument-construction`**：读 `~/.dsh/skills/argument-construction/SKILL.md` 与它的 `~/.dsh/skills/argument-construction/references/report-sections.md`，按同一套 0–11 版块写：（0 封面 / 1 诊断卡+判准建议 / 2 三层交锋表 / 3 概念界定（可选）/ 4 持方论点体系 / 5 核心对象原型资料 / 6 对方观点与反驳 / 7 事实交锋点 / 8 攻防预判 / 9 质询与结辩建议 / 10 论点资料区 / 11 来源索引）。

编号体系：论点 `A1`、交锋点 `F1`、对方路线 `O1`、证据 `E1`、攻防模块 `B1`；来源编号与自己的 xlsx 一致。

**本 skill 额外加的两条硬规矩**：

1. **报告里不许出现辩论过程**。具体的对抗过程、评委裁决、修改过程、场次记录**只进 `辩论实录.md`**，不进报告。报告正文只留本来就该有的东西：定义、判准、论点终稿、资料、攻防预判。封面「版本说明」可以写一行「第 N 场后定稿」这类版本信息——这是报告本来就有的字段，不算过程。
2. **§4 持方论点体系只写我方主张**，不带「对方会说……」。立论不预判反驳，猜对方怎么打属于 §6 / §8 的事。校验脚本 `check_match.py --deliverable` 会扫这一节。

把对抗里真实的攻击与回应喂给 §6 / §8：**§6 的「对方最强版本」优先用对方真实说过的原文**（steelman，不许妖魔化），§8 的攻防对话按对方实际追问链展开，按对抗记录的排版要求写（每组攻防之间空一行，组内每句独立成段）。

写作风格与去 AI 腔清单：照 `argument-construction` 的「写作风格」与「去 AI 腔」两节执行——大白话、不拟人、不比喻，**展开写不许压缩成电报体**，术语第一次出现用一句白话解释，句尾不挂「凸显 / 体现」，不写「不仅……而且……」，「值得注意的是」直接删。

## 《辩论实录》怎么写

实录是给用户和教练看的**过程档案**，主线是「这场在争什么、谁赢了哪一块、哪条论点被怎么改了」。结构固定：

**0. 封面**：辩题、交付档位、场次数、两队名单与角色、起人方式（有没有 `fallback: true`）、制作日期。

**1. 计分表**：每场 7 张技术票 + 1 张印象票的归属，逐场列出，最后一行**累计总分**。技术票按环节拆开列（哪个环节谁赢）。

**2. 共同基准**：诊断卡全文、双方举证责任分配、锁定的判准、事实基准的状态（哪几条有冲突、怎么处理的）。

**3. 每场一节，固定四块**：

- **A. 环节摘要表**：13 行，每行「环节 / 谁 / 时长 / 要点摘要 / 对方当场怎么回」。摘要一两句话，**不抄全文台词**（全文在辩手资料里）。
- **B. 自由辩论发言板**：按时间片列「谁 / 多久 / 打的哪一点」，体现轮转。
- **C. 评委裁决**：7 张技术票（含事实 / 价值 / 身份三层判断与理由）+ 印象票 + 战场总结 + 双方得失（每方「做得好 / 没做好」各一条）+ **6 条论点问题清单与最低修补要求**。
- **D. 场间修改**：双方的报告（有修改 / 无修改）、讨论要点（谁提了什么）、修补清单、资料补充清单（补了哪些来源编号）。

**4. 终局论点档案**：每方 3 个论点的最终结局（存活 / 修补后存活 / 降级 / 删除）、每个论点被修补过几次、哪一场改的。**这里写终局状态，不复述过程。**

**5. 附录**：起人与降级标注、提前收场的原因（如果有）、未闭合项（还挂着没解决的问题）。

实录同样适用写作风格与去 AI 腔清单。

## 校验脚本

数据 JSON 与实录结构写完后，先跑校验，硬项通过才出文件。

```bash
python ~/.dsh/skills/debate-9/scripts/check_match.py <对局记录.json> --tier <精简|标准|完整> [--deliverable <交付文件夹>] [--strict-words]
python ~/.dsh/skills/debate-9/scripts/count_speech.py --dir <某方>\辩手资料
python ~/.dsh/skills/debate-9/scripts/count_speech.py <草稿.md> --unit <环节>
python ~/.dsh/skills/argument-construction/scripts/precheck.py <数据.json> [--md <报告.md>] [--tier <档位>] [--no-link-check]
python ~/.dsh/skills/argument-construction/scripts/generate_report.py xlsx <输出.xlsx> <数据.json>
```

- **对局记录**：`~/.dsh/tmp/<任务名>/match_record.json`（R6），结构见脚本顶部注释与 `references\match-record.md`。它管：场次、13 个环节的顺序与时长、每段发言的 `words`、评委裁决与票数、场间修改、终局论点结局。`--deliverable` 一起用还会核对交付结构、§4 纯净、四份立论类稿字数（H16）、质询与自由辩论的每方总量（H15）；`--strict-words` 才把**报告**字数卡成硬项（默认只告警；立论类稿字数不受这个开关影响，永远是硬项）。
- **口播稿字数**：辩手发言前自查用 `count_speech.py`；交付前主席用 `count_speech.py --dir` 逐方复核一遍。区间真源在 `scripts\speech_bands.py`（语速、区间、哪份稿按哪一段算都只改这一个文件）。
- 提交前要跑完 `check_match.py`（带 `--deliverable`）和两方的 `precheck.py`。**不发 PDF。**
- 免费提示：正方、反方各跑各的 `precheck.py`，两边的来源编号体系互相独立，不要拿一方的编号去对另一方的来源索引。

- 不许把辩论过程写进立论报告
