# 对局记录（match_record.json）结构与校验规则

文件落在 `~/.dsh/tmp/<任务名>/match_record.json`（R6，交付前删掉），UTF-8 无 BOM。
校验脚本：`~/.dsh/skills/debate-9/scripts/check_match.py`。

```bash
python ~/.dsh/skills/debate-9/scripts/check_match.py <record.json> --tier <精简|标准|完整> [--deliverable <交付文件夹>] [--strict-words] [--json]
```

一份记录 = 一整场任务（所有场次都在 `matches` 里）。

## 整体结构

```json
{
  "motion": "辩题原文",
  "tier": "精简|标准|完整",
  "matches": [ Match, ... ],
  "final": Final
}
```

## Match

```json
{
  "n": 1,
  "segments": [ Segment × 13 ],
  "judge": Judge,
  "revisions": [ Revision × 2 ]
}
```

### Segment

十三个发言单元，顺序、phase、side、speaker、target、时长**全部固定**（见下表）。`summary` 非空，是这段发言的要点摘要（不是全文台词；全文在 `辩手资料\` 里）。一辩立论额外带 `points`（本方三个论点的编号）；质询环节额外带 `target`（被质询的辩手）与 `questions`（追问链）；自由辩论用 `seconds_per_side` 而不是 `seconds`，并带 `turns`。

每段还要带 **`words`（口播字数）**，写法四种，脚本都认：

- 逐字稿环节（一辩立论 / 二辩申论 / 三辩小结 / 结辩）：直接写整数 `"words": 780`。
- **质询环节（四质询一 / 三质询二）：按「每方实际发言总量」判 175–215 字**，不判某一句话、也不判问答合计。三种记法都认：
  - `"words": {"问": 195, "答": 195}` —— 直接给两方总量；
  - `"words": {"正方": 195, "反方": 195}`；
  - **推荐：按回合记 `turns`**，每次发言带 `words` 与 `role`（`问` / `答`）或 `side` / `speaker`，脚本自动按方汇总 —— 这样才留得下「问一句、对方答完、再追一句」的短攻防过程。
- 自由辩论：写 `"words": {"正方": 1000, "反方": 1000}`，或者在每个 `turn` 上写 `words`，脚本按 `speaker` 自动归到各方（每方 940–1140）。

**没记 `words` 走软项 `S9`（告警）；记了但出区间走硬项 `H15`（退出码 1）。**

```json
{"phase":"一辩立论","side":"正方","speaker":"正方一辩","seconds":180,"words":780,"summary":"...","points":["A1","A2","A3"]}
{"phase":"四质询一","side":"反方","speaker":"反方四辩","target":"正方一辩","seconds":90,"words":{"问":195,"答":195},"summary":"...","questions":["...","..."]}
{"phase":"四质询一","side":"反方","speaker":"反方四辩","target":"正方一辩","seconds":90,"turns":[{"role":"问","speaker":"反方四辩","words":65,"point":"..."},{"role":"答","speaker":"正方一辩","words":65,"point":"..."}],"summary":"...","questions":["..."]}
{"phase":"自由辩论","side":"双方","seconds_per_side":240,"words":{"正方":1000,"反方":1000},"turns":[{"speaker":"正方一辩","seconds":20,"point":"..."}]}
```

### Judge

```json
{
  "segment_votes": [
    {"phase":"一辩立论","winner":"正方","reason":"...","layers":{"事实":"正方","价值":"反方","身份":"打平"}}
  ],
  "impression_vote": {"winner":"反方","reason":"..."},
  "battle_summary": "总结战场……",
  "gains_losses": [
    {"side":"正方","good":"...","bad":"..."},
    {"side":"反方","good":"...","bad":"..."}
  ],
  "argument_issues": [
    {"side":"正方","target":"A1","issue":"...","demand":"..."}
  ]
}
```

- `segment_votes`：**恰好 7 条**，`phase` 覆盖 一辩立论 / 四质询一 / 二辩申论 / 三质询二 / 三辩小结 / 自由辩论 / 结辩，不重不漏。`winner` ∈ {正方, 反方}，`reason` ≥ 10 字。`layers` 三层（事实 / 价值 / 身份）各写 正方 / 反方 / 打平。
- `impression_vote`：`winner` ∈ {正方, 反方}，`reason` ≥ 10 字。
- `battle_summary` ≥ 50 字。
- `gains_losses`：恰好 2 条，双方各一条。
- `argument_issues`：**恰好 6 条**，正方 A1/A2/A3 与 反方 A1/A2/A3 各一条。这轮没问题就显式写 `issue: "无"`、`demand: "保持"`。
- 计分：每张票 1 分，一场 8 分，多场累计（只在《辩论实录》里体现，不进记录字段）。

### Revision

```json
{"side":"正方","report":"有修改","discussion":[{"who":"正方二辩","point":"..."}],
 "patches":[{"id":"A1","action":"修补","detail":"...","cost":"无"}],
 "materials":[{"researcher":"正方资料员","added":["E9","E10"],"note":"..."}]}
```

```json
{"side":"反方","report":"无修改","reason":"对方质询没有碰到我方机制环节","patches":[],"discussion":[],"materials":[]}
```

- 每场**恰好 2 条**，双方各一条。
- `report` ∈ {有修改, 无修改}。
- `report = 有修改` → `patches` 非空，每条含 `id`（A1/A2/A3）、`action` ∈ {修补, 换证据, 改判准, 让步删点, 拒绝并说明}、`detail` ≥ 8 字、`cost` 非空（没让步写「无」）。
- `report = 无修改` → `patches` **必须为空**，且 `reason` ≥ 8 字。
- `discussion` / `materials` 可选，可以空数组。

## Final

```json
{
  "left_early": false,
  "left_early_reason": "",
  "arguments": {
    "正方": [{"id":"A1","result":"修补后存活","patches":2}],
    "反方": [{"id":"A1","result":"存活","patches":0}]
  }
}
```

- 场次数：精简 2 / 标准 3 / 完整 4。**提前收场**（双方均报告无修改）时 `left_early: true`，允许少打，但必须 ≥ 1 场且 `left_early_reason` ≥ 10 字。
- `arguments` 含 正方 / 反方 两键，各恰好 3 条，`id` 为 A1/A2/A3，`result` ∈ {存活, 修补后存活, 降级, 删除}，`patches` 是非负整数。
- **每方 `result` ∈ {存活, 修补后存活} 的条数必须 = 3**：掉到 3 个以下要回炉补料，不许硬凑。

## 交付结构校验（`--deliverable` 时）

- `<目录>\辩论实录.md`
- `<目录>\正方\立论报告.md`、`<目录>\反方\立论报告.md`
- `<目录>\正方\资料.xlsx`、`<目录>\反方\资料.xlsx`
- `<目录>\正方\辩手资料\` 与 `<目录>\反方\辩手资料\` 各 7 个 md，文件名包含：一辩立论稿 / 二辩申论稿 / 三辩质询稿 / 三辩小结稿 / 四辩结辩稿 / 自由辩要点 / 数据资料
- 两份立论报告的「持方论点体系」小节不许出现预判反驳句式（对方会 / 反方会……）——硬项 `H14`
- 报告正文出现「第 N 场 / 技术票 / 印象票 / 评委 / 辩论实录」这类辩论过程字样只告警——软项 `S8`，过程只该进 `辩论实录.md`
- **立论类稿**的字数要落在区间内——硬项 `H16`：`一辩立论稿.md` 只数 `## 立论` 节（700–860）、`二辩申论稿.md` 只数 `## 申论` 节（470–570）、`三辩小结稿.md` 整份（470–570）、`四辩结辩稿.md` 只数 `## 结辩` 节（700–860）。**`## 被质询时的答话`、`## 质询` 这些段落不计入任何区间**：它们挤占立论的时间预算，必须分开算。
- **要点类稿**（`三辩质询稿.md`、`自由辩要点.md`）**不卡字数**，超上限 3 倍才告警——软项 `S10`（提示「写成了逐字稿」）。`数据资料.md` 也不卡。

## 口播字数（真源：`scripts\speech_bands.py`）

时长换算成能念多少字：基准语速 **260 字/分钟**，区间 = 中心值 ±10%，取整到 10。口径与报告一致（去空白字符数含标点）。区间内不管，低于下限（时间没用满）或高于上限（念不完）都要改稿。

**两类稿两种管法**：立论类稿写成逐字稿、按上面 `H16` 的分段口径卡；要点类稿（`三辩质询稿.md` / `自由辩要点.md`）只写弹药不写台词，不卡。**质询与自由辩论不卡稿子，改卡「每方实际发言总量」**（质询 175–215、自由辩论 940–1140），记在实录的 `words` / `turns` 里。

单个环节自查 / 整方批量自查：

```bash
python ~/.dsh/skills/debate-9/scripts/count_speech.py <草稿.md> --unit <环节> [--part 质询]
python ~/.dsh/skills/debate-9/scripts/count_speech.py --dir <某方>\辩手资料
python ~/.dsh/skills/debate-9/scripts/count_speech.py --list
```

`--part` 只数标题含该关键字的某一节（例：`--part 质询` 只量四辩结辩稿里的质询节）。`--unit` 给立论类环节时，脚本自动只数该环节对应的那一段（答话、质询段剔除）。

稿件与环节的对应：`一辩立论稿`→立论节 / `二辩申论稿`→申论节 / `三辩小结稿`→整份 / `四辩结辩稿`→结辩节 / `三辩质询稿`、`自由辩要点`→要点类不卡。

## 报告字数（`--strict-words` 时卡，默认只告警）

口径：去掉全部空白字符后的字符数（含标点）。下限：精简 20000 / 标准 35000 / 完整 50000。正反两方**各算各的**。**只数 `正方\立论报告.md` 与 `反方\立论报告.md` 两份**，辩手稿、数据资料、辩论实录一律不计入。

## 硬项 / 软项编号

脚本沿用 `check_debate.py` 的风格：硬项 `H*` 失败退出码 1（0 全过，2 参数或文件错误），软项 `S*` 只告警。具体编号以脚本实现为准。

- 硬项：`H1`–`H11` 记录本身（场次、环节、时长、评委票、修改、终局结局），`H12` 交付结构，`H13` 报告字数下限（默认只告警，`--strict-words` 才升级），`H14` §4 不预判反驳，`H15` 每段发言字数落区间（质询按每方总量 175–215、自由辩按每方 940–1140），`H16` 四份立论类稿字数落区间。
- 软项：`S1`–`S7` 记录质量的提示，`S8` 报告混入辩论过程，`S9` 某段没记 `words`，`S10` 要点类稿超上限 3 倍（疑似写成逐字稿）。
